# 食物銀行管理系統

純前端食物銀行管理後台，無需伺服器，開啟 HTML 即可運行。  
提供**會員管理**、**倉儲管理**、**數據分析**、**點數兌換**四大核心功能，專為食物銀行日常作業流程設計。

## 快速開始

### 環境需求

- 現代瀏覽器（Chrome 90+ / Edge 90+ / Firefox 88+ / Safari 15+）
- 無需 Node.js、無需網路連線、無需任何安裝步驟

### 啟動方式

```
直接用瀏覽器開啟：

  index.html   →  會員登入 / 會員中心
  admin.html   →  管理後台
```

> 所有資料儲存於瀏覽器 `localStorage`，首次開啟時自動寫入預設示範資料。

### 預設帳號

#### 管理員

| 欄位 | 值 |
|------|----|
| 帳號 | `admin` |
| 密碼 | `admin123` |

> 登入後建議立即至「🔑 修改管理員密碼」變更預設密碼。

#### 示範會員

| 姓名 | 電話（登入帳號） | 密碼 | 備註 |
|------|----------------|------|------|
| 王大明 | `0912345678` | `123` | 一般會員，點數 1,500 |
| 李阿姨 | `0987654321` | `123` | 一般會員，點數 300 |
| 陳建國 | `0955111222` | 首次登入自行設定 | 新會員，未完成初始設定 |

```

│
├── 會員端 (index.html)

│   ├── 點數餘額查詢
│   └── 個人資料維護

│   ├── 📊 資料統計（全覽 / 年報 / 月報 / 日報）

│   ├── 👥 會員管理（新增 / 編輯 / 批量補點）
```

```
index.html  ──登入成功──►  index.html（會員中心）

```

管理員可在會員登入頁直接以管理員帳號登入，系統會自動導向後台。

## 功能說明

### 管理後台（`admin.html`）

---

#### 📊 資料統計

提供四種時間維度的報表切換（頁籤式），所有圖表使用 Chart.js 渲染。

**全覽（Overview）**

| 指標卡片 | 說明 |
|---------|------|
| 總會員數 | 所有已建立的會員帳號數量 |
| 累積兌換次數 | 歷史核銷總筆數 |
| 已核銷總點數 | 所有兌換消耗的點數加總 |
| 低庫存品項 | 庫存量 ≤ 5 件的品項數量（紅色警示） |

圖表：
- **現有庫存分類佔比**（圓餅圖）：依分類顯示目前庫存數量比重
- **全期各分類兌換量比重**（圓餅圖）：依分類顯示歷史核銷次數比重
- **歷年兌換統計**（長條圖）：每年核銷點數總計
- **本年度每月兌換趨勢**（折線圖）：當年各月兌換筆數

**RFM 會員活躍度分群**

依每位會員最近一次兌換距今天數自動分群：

| 群體 | 條件 | 顏色 |
|------|------|------|
| 活躍 | 30 天內有兌換紀錄 | 綠色 |
| 沉睡 | 31–90 天未兌換 | 橘色 |
| 流失 | 超過 90 天未兌換 | 紅色 |
| 從未兌換 | 無任何兌換紀錄 | 灰色 |

**點數異動紀錄**：預設顯示最近 15 筆，可展開查看全部，記錄類型包含初始發放、補點、扣點、兌換核銷。

---

**年報（Yearly）**

- 選擇年份（下拉選單，自動列出有資料的年份）
- 顯示：年度兌換次數、年度核銷點數、年度新增會員數
- 圖表：月度兌換趨勢（長條圖）、年度分類兌換佔比（圓餅圖）

**月報（Monthly）**

- 選擇年份與月份
- 顯示：兌換次數、核銷點數、不重複服務人次，附與上月同期比較（▲▼百分比）
- 圖表：日兌換趨勢（長條圖）、月度分類兌換佔比（圓餅圖）

**日報（Daily）**

- 選擇特定日期（預設當天）
- 顯示：當日兌換次數、核銷點數、服務人次（不重複）
- 圖表：小時兌換分佈（長條圖，0–23 時）
- 明細表：列出當日所有兌換紀錄（時間、會員、物品分類、扣點）

---

#### 📦 庫存管理

**搜尋與篩選**
- 關鍵字搜尋（條碼或品名）
- 分類下拉篩選

**庫存列表**

每筆品項顯示：條碼、品名、分類標籤（帶色）、庫存量（低庫存橘色警示 / 缺貨紅色），預設點數。

庫存狀態標示：
- 庫存量 = 0：顯示「缺貨」紅色徽章
- 庫存量 ≤ 5：顯示「庫存偏低」橘色徽章

**行內編輯**

點擊「編輯」後該列變為藍底輸入狀態，可直接修改品名、分類、庫存量、預設點數。頂部出現 sticky 儲存列，支援多列同時編輯後一次批次儲存。儲存時會同步更新兌換歷史中的分類資訊。

**批量掃描入庫**

點擊「+ 開始批量掃描建檔入庫」開啟 Modal：

1. 將游標聚焦到掃描輸入框
2. 以條碼掃描槍逐一刷入條碼：
   - **現有品項**：顯示品名、分類、現有庫存量，填入補充數量
   - **全新品項**：顯示「全新建檔」標籤，需填入品名、分類、預設點數、入庫數量
3. 可繼續刷入其他條碼，清單內同一條碼不可重複
4. 確認後一次送出，同時更新庫存並寫入入庫歷史 Log

**分類維護**

- 新增、刪除分類
- 為每個分類選擇顯示色票（8 種配色）
- 刪除有品項使用中的分類時會出現確認提示

**入庫歷史**：預設顯示最近 15 筆，可展開查看全部，記錄時間、條碼、品名、入庫數量、備註。

---

#### 👥 會員管理

**搜尋**：支援姓名、電話、條碼關鍵字即時搜尋。

**會員列表欄位**

| 欄位 | 說明 |
|------|------|
| 選取框 | 勾選會員用於批量補點 |
| 會員條碼 | 系統自動產生（`ID-電話`格式） |
| 姓名 | 會員全名 |
| 電話 | 登入帳號，唯一識別 |
| 狀態 | 使用中（綠）/ 已過期（紅）|
| 剩餘點數 | 目前可用點數 |
| 操作 | 編輯 / 密碼還原 / 兌換紀錄 |

**行內編輯**：點擊「編輯」後可直接修改姓名、電話、點數、狀態，頂部出現 sticky 儲存列，支援多列同時編輯後批次儲存。點數有變動時自動記入點數異動 Log。

**新增會員**：填入姓名與電話，系統自動：
- 產生流水號 ID（`M001`、`M002`…）
- 發放 1,000 初始點數並記入 Log
- 設定為首次登入狀態（會員首次登入需自行設定密碼）

**密碼還原**：將指定會員密碼重設為其手機號碼，下次登入後建議自行修改。

**兌換紀錄查閱**：點擊「紀錄」開啟 Modal，顯示該會員所有兌換明細（時間、物品、分類、扣點），依時間倒序排列。

**匯入會員資料**

點擊「📥 匯入會員」，選擇 CSV 檔案（格式與「會員清單」匯出相同）：

1. 選擇 CSV 檔案後自動解析並顯示預覽
2. 選擇遇到已存在 ID 時的處理方式：
   - **跳過**（僅新增模式）：已存在的 ID 一律略過，只新增不存在的
   - **覆蓋更新**：已存在的 ID 更新資料，不存在的新增
3. 預覽表格以顏色標示每列的處理動作：
   - 🟢 新增 / 🔵 更新 / 灰 跳過 / 🔴 錯誤
4. 確認後執行，點數異動自動記入 Log

| 驗證規則 | 說明 |
|---------|------|
| 必要欄位 | `姓名`、`電話` 不可為空 |
| 電話唯一性 | 電話已被其他 ID 使用時標記為錯誤 |
| ID 衝突 | `會員ID` 為空時自動產生；與現有 ID 衝突時依選擇模式處理 |
| CSV 內重複 | 同一 CSV 內電話或 ID 重複時標記為錯誤 |
| 點數下限 | 更新時若點數變動，記入點數 Log；不可為負數 |

**批量補點**

1. 勾選一或多位會員（或點擊表頭「全選」）
2. 頂部出現綠色操作列，顯示已選取人數
3. 點擊「💰 批量補點」開啟 Modal
4. 輸入異動點數（正數補點、負數扣點）與必填原因
5. 輸入點數後即時顯示每位會員的前後點數變化預覽
6. 確認送出後套用至所有選取會員，每筆各自記入點數異動 Log
7. 若會員點數扣至負數，自動 floor 為 0（不會出現負點數）

#### 🛒 掃碼兌換作業

專為現場工作人員設計的快速核銷流程，支援條碼掃描槍連續操作。

**步驟一：辨識會員**

在「步驟一」輸入框刷入或輸入以下任一種識別方式：
- 會員條碼（例如 `M001-0912345678`）
- 會員 ID（例如 `M001`）
- 電話號碼（例如 `0912345678`）

系統驗證通過後，顯示會員姓名與帳戶餘額，進入步驟二。

**步驟二：掃描物品**

連續刷入物品條碼，每次刷入後：
- 物品加入清單，顯示條碼、品名、剩餘庫存、扣除點數
- 帳戶餘額即時更新（顯示兌換後剩餘點數）
- 若累計點數超過餘額：
  - 掃描區出現紅色警示橫幅，說明缺少點數
  - 送出按鈕自動停用並變灰
  - 移除項目後若點數恢復充足，警示自動消失

**清單操作**
- 點擊列末「移除」刪除單一項目
- 點擊「🗑️ 清空清單」清除所有項目（需確認）
- 點擊「更換會員」重新選擇會員（清單同步清空）

**送出核銷**

確認無誤後點擊「確認扣點並送出核銷」：
1. 扣除會員點數
2. 扣減各物品庫存量
3. 每件物品各建立一筆兌換紀錄（含流水序號）
4. 每件物品各記入一筆點數異動 Log（類型：兌換核銷）

**防呆機制**
- 過期會員掃描時即時攔截，無法進行兌換
- 物品庫存不足時（含本次已掃描數量）即時警示，不允許加入清單
- 點數不足時送出按鈕停用，防止誤送

#### 🗂️ 資料管理

**CSV 匯出**

| 匯出項目 | 包含欄位 |
|---------|---------|
| 會員清單 | ID、姓名、電話、狀態、剩餘點數、加入日期、生日、地址、條碼 |
| 兌換紀錄 | 交易序號、兌換時間、會員ID、會員姓名、物品條碼、物品名稱、分類、扣除點數 |
| 點數異動紀錄 | 記錄ID、時間、會員ID、會員姓名、異動點數、類型、備註 |
| 入庫歷史 | 記錄ID、時間、條碼、品項名稱、入庫數量、備註 |
| 現有庫存 | 條碼、名稱、分類、庫存量、預設點數 |

- 所有 CSV 含 UTF-8 BOM，可直接以 Excel 或 Google 試算表開啟，繁體中文正確顯示
- 檔名自動帶入匯出日期，例如 `兌換紀錄_2026-04-01.csv`

**清除歷史資料**

用於釋放 localStorage 空間（建議匯出備份後再清除）：

1. 選擇起始日期與結束日期（兩端日期均包含當天）
2. 勾選要清除的資料類型：兌換紀錄 / 點數異動紀錄 / 入庫歷史
3. 點擊「預覽將刪除的筆數」確認影響範圍（無法刪除當前庫存與會員資料）
4. 點擊「執行清除」，在 Modal 中手動輸入「**確認清除**」四個字才能啟用確認按鈕
5. 完成後自動重新整理相關頁面

### 會員端（`index.html`）

#### 登入流程

```
輸入電話 + 密碼
    │
    ├── 首次登入（isFirstLogin = true）
    │       └── 強制進入設定頁面
    │           ├── 設定登入密碼（必填，至少 6 字元）
    │           ├── 填寫生日（選填）
    │           └── 填寫地址（選填）
    │               └── 完成後進入會員中心
    │
    └── 一般登入
            └── 驗證密碼 → 進入會員中心
```

#### 會員中心功能

**專屬兌換區**
- 顯示 CODE128 格式會員條碼（SVG，供掃描槍讀取）
- 顯示目前剩餘點數（大字顯示）
- 列出所有兌換紀錄（兌換時間、物品名稱、扣除點數），依時間倒序排列

**個人資料設定**
- 重新設定密碼（留白代表不更改）
- 修改生日、地址
- 姓名與電話欄位為唯讀（由管理員管理）

## 操作流程

### 典型每日作業流程

```
開始服務前
    管理員登入後台
    → 「庫存管理」確認各品項庫存量
    → 如有新物資到貨：「+ 開始批量掃描建檔入庫」

服務進行中
    「掃碼兌換作業」→「+ 開始多筆掃碼核銷」
    → 刷入會員條碼（步驟一）
    → 連續刷入物品條碼（步驟二）
    → 確認總點數與餘額後送出

服務結束後
    → 「資料統計」→「日報」查看當日服務概況
    → 確認低庫存品項，準備補貨

定期維護
    → 「資料管理」匯出 CSV 備份
    → 視需要清除指定區間歷史 Log
    → 「資料統計」→「月報」產出報表
```

### 新會員加入流程

```
管理員：「會員管理」→「+ 新增會員」→ 填入姓名、電話
    └── 系統自動發放 1,000 初始點數

會員首次到場：出示手機號碼給工作人員掃描或輸入
    └── 若尚未自行登入設定密碼：工作人員可協助以手機直接開啟 index.html 完成設定
```

## 資料結構

所有資料以 JSON 格式存於 `localStorage`，以下為各資料集的欄位說明。

### 會員（`foodbank_members`）

```jsonc
{
  "id": "M001",              // 會員 ID（流水號，系統自動產生）
  "name": "王大明",           // 姓名
  "phone": "0912345678",     // 電話（登入帳號，唯一）
  "password": "sha256hash",  // 密碼 SHA-256 雜湊值（首次登入前為空字串）
  "isFirstLogin": false,     // 是否為首次登入
  "points": 1500,            // 剩餘點數
  "joinDate": "2025-01-15",  // 加入日期（YYYY-MM-DD）
  "birthday": "1980-05-20",  // 生日（選填）
  "address": "台北市信義區",  // 地址（選填）
  "status": "active",        // 帳號狀態：active / expired
  "barcode": "M001-0912345678" // 條碼字串
}
```

### 庫存品項（`foodbank_inventory`）

```jsonc
{
  "barcode": "IT001",     // 物品條碼（唯一識別）
  "name": "白米 2kg",     // 品名
  "category": "主食",     // 分類
  "quantity": 50,         // 目前庫存量
  "pointsCost": 200       // 兌換所需點數
}
```

### 兌換紀錄（`foodbank_redemptions`）

```jsonc
{
  "id": "R001",                      // 交易序號
  "memberId": "M001",                // 會員 ID
  "itemBarcode": "IT001",            // 物品條碼
  "itemName": "白米 2kg",            // 物品名稱（快照）
  "category": "主食",                // 分類（快照）
  "pointsCost": 200,                 // 扣除點數
  "date": "2026-01-20T10:00:00.000Z" // ISO 時間字串
}
```

### 點數異動 Log（`foodbank_points_log`）

```jsonc
{
  "id": "PL1234567890",   // 記錄 ID（PL + timestamp）
  "memberId": "M001",
  "memberName": "王大明",
```

## 安全性說明

> 本系統採純前端架構，適合**內部展示、試驗場景或網路隔離環境**使用。

### 已實作的防護措施

| 措施 | 實作方式 |
|------|---------|
| 密碼雜湊 | SHA-256（Web Crypto API），不明文儲存；舊版明文密碼於首次驗證後自動升級（懶遷移） |
| 管理員 Session | 隨機 32 bytes Token，以 SHA-256 hash 存於 `sessionStorage`，關閉分頁即失效 |
| XSS 防護 | 所有動態輸出皆通過 `escapeHtml()` 跳脫（`&`, `<`, `>`, `"`, `'`） |
| 過期帳號攔截 | `status: expired` 的會員於登入時與兌換時雙重攔截 |
| localStorage 寫入保護 | 所有寫入透過 `safeSetItem()` 捕捉 `QuotaExceededError`，防止靜默失敗 |

### 架構限制（正式上線前需解決）

- **所有資料儲存於 `localStorage`**，瀏覽器開發者工具可直接讀取與修改，安全性無法依賴前端機制保障
- 管理員帳號資料與會員資料存於同一來源，理論上具備 JavaScript 執行環境的使用者皆可存取
- 無多管理員機制，無操作審計（誰在何時做了什麼）
- **建議**：若需正式對外服務，遷移至真實後端（Node.js / Python + PostgreSQL / SQLite）並以 HTTPS 提供服務

## 注意事項與限制

**資料儲存**
- 所有資料僅存於**當前瀏覽器的 localStorage**，換瀏覽器、換裝置、開無痕視窗均無法存取同一份資料
- 清除瀏覽器網站資料（Clear Site Data）會導致**所有資料永久遺失**，請定期至「資料管理」匯出 CSV 備份

**容量上限**
- `localStorage` 上限約 5–10 MB（依瀏覽器而異）
- 長期運營後兌換紀錄與 Log 將持續累積，建議每季至「資料管理」匯出後清除歷史 Log

**多視窗 / 多裝置**
- 不支援多裝置同步，不建議同時在多個視窗操作後台，避免資料覆蓋

**其他限制**
- 僅支援單一管理員帳號
- 會員資料支援 CSV 匯入（詳見「會員管理」章節），但**庫存**不支援 CSV 批量匯入，如需大量建立品項請使用「批量掃描入庫」功能或自行修改 `initDB()` 預設資料
- 圖表與條碼功能依賴 CDN，完全離線使用時需預先快取對應 JS 資源
